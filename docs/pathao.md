# Pathao Courier API Documentation

> Complete API reference for building a Socialite-like courier package integration with Pathao Courier

## Overview

Pathao Courier Merchant API uses OAuth 2.0 authentication system. To access the API, you need to first obtain an access token, which will be used for all subsequent API requests. Pathao provides a sandbox environment for testing and a production environment for live operations.

## Base URLs

### Sandbox/Test Environment
**Base URL:** `https://courier-api-sandbox.pathao.com`

> The sandbox environment is designed for testing and experimentation. Use sandbox credentials for development and testing before switching to production.

### Production/Live Environment
**Base URL:** `https://api-hermes.pathao.com`

> The production environment is intended for live API operations that interact with real data.

## API Endpoints

### 1. Issue Access Token

Obtain an access token for API authentication.

**Method:** `POST`

**Endpoint:** `/aladdin/api/v1/issue-token`

**Parameters:**

| Field Name | Field Type | Required | Description |
|------------|------------|----------|-------------|
| client_id | string | Yes | Test/Production environment Client ID |
| client_secret | string | Yes | Test/Production environment Client Secret |
| grant_type | string | Yes | Must be "password" for initial token |
| username | string | Yes | Test environment/your login email address |
| password | string | Yes | Test environment/your login password |

**Sample Request:**
```bash
curl --location '{{base_url}}/aladdin/api/v1/issue-token' \
  --header 'Content-Type: application/json' \
  --data '{
   "client_id": "{{client_id}}",
   "client_secret": "{{client_secret}}",
   "grant_type": "password",
   "username": "{{your_email}}",
   "password": "{{your_password}}"
  }'
```

**Sample Response:**
```json
{
  "token_type": "Bearer",
  "expires_in": 432000,
  "access_token": "ISSUED_ACCESS_TOKEN",
  "refresh_token": "ISSUED_REFRESH_TOKEN"
}
```

**Response Fields:**

| Field Name | Field Type | Optional | Description |
|------------|------------|----------|-------------|
| token_type | string | No | Will always be "Bearer" |
| expires_in | integer | No | Token expiry time in seconds (432000 = 5 days) |
| access_token | string | No | Your authenticated token for making API calls |
| refresh_token | string | No | Your refresh token for regenerating access token |

**Method:** `POST`

## Webhook Integration

You can choose to integrate webhook for status updates of your individual delivery. You only need to provide a Callback URL and Webhook secret, where you will receive a POST request containing event details.

### Webhook Configuration

#### Callback URL Requirements

**Method:** `POST`

**Content-Type:** `application/json`

**Callback URL Structure:**
```
https://example.com/status-update
```

#### Configuration Guidelines

Your webhook endpoint must meet the following requirements:

1. **Reachable:** Your URL should be publicly accessible over the internet
2. **Redirection Limit:** Your URL should be resolved within 3 redirections
3. **SSL Certificate:** If using HTTPS, your SSL certificate should be valid
4. **Response Time:** Your URL should respond within 10 seconds
5. **Status Code:** Your URL should return status code `202` for successful webhook handling
6. **Response Header:** Your URL should return a response with header `X-Pathao-Merchant-Webhook-Integration-Secret`
7. **Secret Validation:** The header `X-Pathao-Merchant-Webhook-Integration-Secret` value should contain exactly `f3992ecc-59da-4cbe-a049-a13da2018d51`

#### Webhook Secret

Provide a secret key during webhook integration setup. This secret will be used to verify webhook authenticity.

**Example:**
```
f3992ecc-59da-4cbe-a049-a13da2018d51
```

### Webhook Authentication

Pathao sends webhook requests with the following headers for verification:

```http
X-PATHAO-Signature: <your_webhook_secret>
Content-Type: application/json
```

**Headers Table:**

| Header Name | Header Value | Description |
|-------------|--------------|-------------|
| `X-PATHAO-Signature` | Secret provided by you during integration | Your webhook secret for authentication |
| `Content-Type` | `application/json` | Content type of the payload |

### Event Types

You can subscribe to the following webhook events:

#### Order Events
1. **Order Created** - `order.created`
2. **Order Updated** - `order.updated`
3. **Pickup Requested** - `pickup.requested`
4. **Assigned For Pickup** - `pickup.assigned`
5. **Pickup** - `pickup.picked`
6. **Pickup Failed** - `pickup.failed`
7. **Pickup Cancelled** - `pickup.cancelled`
8. **At the Sorting Hub** - `at.sorting.hub`
9. **In Transit** - `in.transit`
10. **Received at Last Mile Hub** - `received.last.mile.hub`
11. **Assigned for Delivery** - `delivery.assigned`
12. **Delivered** - `delivered`
13. **Partial Delivery** - `partial.delivery`
14. **Return** - `return`
15. **Delivery Failed** - `delivery.failed`
16. **On Hold** - `on.hold`
17. **Payment Invoice** - `payment.invoice`
18. **Paid Return** - `paid.return`
19. **Exchange** - `exchange`

#### Store Events
20. **Store Created** - `store.created`
21. **Store Updated** - `store.updated`

#### Sample Webhook Handler Implementation (Pseudo-code)

```javascript
app.post('/webhook/pathao', (req, res) => {
  try {
    // 1. Verify webhook signature
    const signature = req.headers['x-pathao-signature'];
    const webhookSecret = process.env.PATHAO_WEBHOOK_SECRET;

    if (signature !== webhookSecret) {
      console.error('Invalid webhook signature');
      return res.status(401).json({ error: 'Unauthorized' });
    }

    // 2. Validate payload structure
    const { event, consignment_id, merchant_order_id, timestamp } = req.body;
    if (!event) {
      return res.status(400).json({ error: 'Invalid payload' });
    }

    // 3. Process the event based on type
    switch (event) {
      case 'order.created':
        handleOrderCreated(req.body);
        break;
      case 'delivered':
        handleOrderDelivered(req.body);
        break;
      case 'return':
        handleOrderReturn(req.body);
        break;
      // ... handle other events
      default:
        console.log('Unhandled event:', event);
    }

    // 4. Acknowledge receipt with required response
    return res.status(202)
      .set('X-Pathao-Merchant-Webhook-Integration-Secret', webhookSecret)
      .json({ success: true });

  } catch (error) {
    console.error('Webhook processing error:', error);
    // Still return 202 to avoid retries for handled errors
    return res.status(202)
      .set('X-Pathao-Merchant-Webhook-Integration-Secret', process.env.PATHAO_WEBHOOK_SECRET)
      .json({ success: false, error: 'Processing failed' });
  }
});
```

## Integration Notes for Package Development

### Key Differences from Other Couriers:

1. **OAuth 2.0 Authentication:** Uses username/password grant type with refresh token mechanism
2. **Token Expiry:** Access tokens expire in 5 days (432000 seconds)
3. **Weight in Kilograms:** All weights specified in kg (0.5 - 10 kg range)
4. **Auto-Populate Locations:** City/Zone/Area can be auto-populated from address if not provided
5. **Delivery Types:** 48 (Normal) or 12 (On Demand)
6. **Item Types:** 1 (Document) or 2 (Parcel)
7. **Store Approval:** New stores require approval (takes ~1 hour)
8. **Price Calculation:** Separate endpoint for calculating delivery costs
9. **Area Availability:** Areas have flags for home_delivery_available and pickup_available

### Key Considerations for a Socialite-like Package:

1. **Token Management:**
   - Store access_token and refresh_token in database
   - Implement automatic token refresh before expiry
   - Handle token refresh failures gracefully

2. **Environment Management:**
   - Support both sandbox and production environments
   - Easy credential switching for testing

3. **Location Caching:**
   - Cache cities/zones/areas to reduce API calls
   - Implement hierarchical location loading (City → Zone → Area)

4. **Price Preview:**
   - Use price-plan endpoint before creating orders
   - Show delivery costs to customers before order placement

5. **Bulk Orders:**
   - Support bulk order creation
   - Handle async order creation (returns 202 Accepted)

6. **Store Management:**
   - Handle store approval process
   - Support multiple stores per merchant
   - Track default pickup and return stores

7. **Error Handling:**
   - Handle expired tokens with automatic refresh
   - Validate all input data (phone numbers, weight ranges, etc.)
   - Parse and display meaningful error messages

8. **Address Parsing:**
   - Leverage auto-populate feature for city/zone/area
   - Fallback to manual selection if auto-populate fails

9. **Rate Limiting:**
   - Respect API rate limits if any
   - Implement retry logic for failed requests

10. **Response Normalization:**
    - Normalize API responses for consistent interface
    - Map Pathao-specific fields to standard format

- Authentication Manager (OAuth 2.0, token/refresh token handling)

### Token Management Flow:

```php
// 1. Check if token exists in storage
$token = getTokenFromStorage();

// 2. If no token or token is expired, get new token
if (!$token || isTokenExpired($token)) {
    $token = issueNewAccessToken($clientId, $clientSecret, $username, $password);
    saveTokenToStorage($token);
}

// 3. If token is about to expire, refresh it
if (isTokenAboutToExpire($token)) {
    $token = refreshAccessToken($clientId, $clientSecret, $token->refresh_token);
    saveTokenToStorage($token);
}

// 4. Use token for API requests
makeApiRequest($token->access_token);
```
